# 任务栏透明与设置界面迁移设计

## 目标

在不改变任务栏横向指标条布局的前提下：

- 在当前 Windows 11 IoT 企业版 LTSC 24H2 上实现完全透明任务栏（`alpha = 0`）。
- 保留 Windows 10/经典任务栏现有实现入口，为后续兼容预留选择路径。
- 使用 `D:\User\Desktop\template.html` 替换设置窗口的视觉布局，并接入现有实时数据和操作。
- 让设置窗口、任务栏组件在 DPI、分辨率和主屏变化后重新计算逻辑尺寸与位置。
- 将 GPT 刷新周期固定为 60 秒，点击 GPT 卡片切换余量/已用量，保留手动刷新。
- 通过启动参数或程序目录配置文件提供代理，不再在界面中编辑代理。

## 不在本次范围内

- 不修改任务栏横向 CPU、内存、温度、磁盘、网络和 GPT 指标条的视觉布局。
- 不实现 GPT 重置按钮或重置额度界面。
- 不调用、捆绑或复制 TranslucentTB；仅参考其 Windows 任务栏处理思路自行实现。
- 不承诺本轮完整支持所有 Windows 10/11 构建和第三方经典任务栏替换工具。
- 不进行无关重构，不删除现有数据库字段或后端命令。

## 任务栏透明架构

### 路径选择

启动时读取真实 Windows 构建号，并选择首选实现：

- Windows 11 22H2 及更新的 XAML 任务栏：使用本项目自有的 Explorer Helper/TAP 路径。
- Windows 10、Windows 11 21H2 或经典任务栏：使用现有 `SetWindowCompositionAttribute` 路径。

版本号只负责选择首选路径；实现还会检查所需 DLL、导出函数、任务栏窗口和 XAML 目标是否存在。检测失败时写入现有日志，不循环尝试危险操作。

### Windows 11 24H2 路径

新增独立 Windows Helper DLL。主进程通过 Windows XAML Diagnostics/TAP 机制让 Helper 进入 Explorer 的任务栏 XAML 上下文。Helper 只负责定位当前构建中的任务栏背景对象并把背景画刷改为透明色（`ARGB = 0x00000000`）。关闭透明模式时恢复系统默认画刷。

Helper 不承载业务状态、不访问网络或数据库。DLL 入口不执行复杂工作；初始化、查找和恢复操作在独立工作入口中完成，错误通过明确的状态码返回主进程并写入 `widget.log`。

本轮只保证当前 24H2 构建的 XAML 元素路径。Windows 版本选择与 Helper 调用边界保持集中，后续构建变化只扩展该模块，不改前端配置或业务代码。

### 经典任务栏路径

复用并修正现有 `SetWindowCompositionAttribute` 实现：

- `Clear` 使用 `ACCENT_ENABLE_TRANSPARENTGRADIENT` 和 `gradient_color = 0x00000000`。
- `Off` 恢复系统默认合成状态。
- 保留主任务栏窗口查找；多显示器任务栏枚举作为后续扩展点，本轮不扩大范围。

### 生命周期与重新应用

透明管理器在以下时机应用或恢复效果：

- 应用启动并且 Explorer/任务栏已经就绪。
- 用户改变透明开关。
- 收到 `TaskbarCreated`（Explorer 重启）。
- 收到显示器、工作区或 DPI 变化通知。

采用系统消息驱动，不使用高频轮询。应用正常退出时尽力恢复系统默认任务栏外观；恢复失败只记录日志，不阻止退出。

## 设置窗口迁移

### 视觉实现

以 `template.html` 为唯一视觉基准，将其结构转换为 Vue 模板和项目内 CSS：

- 不在运行时加载 Tailwind CDN 或 Google Fonts。
- 不引入 Tailwind 构建链，避免为一页固定布局增加配置文件和构建复杂度。
- 通过 npm 的本地字体包打包 Inter、Manrope、JetBrains Mono，并提供 Segoe UI、Cascadia Mono 等系统字体回退。
- 保留模板的玻璃卡片、顶部栏、筛选区、72px 指标卡片、折线、进度条和配色。
- 文案按现有中文界面处理，短指标标签保留 CPU、MEM、TMP、NET、DSK、GPT。

### 数据与交互映射

- 顶部 Log File、Quit 分别调用现有打开日志和退出命令。
- POS 使用互斥按钮/选择控件，映射现有 `left`、`right`。
- TASKBAR 透明开关映射 `off`、`clear`。
- 指标筛选继续使用现有可见性配置；NET 同时控制上传和下载。
- CPU、内存、温度和网络卡片继续使用现有历史数据绘制折线；MAX 从当前已加载的历史点计算。
- 磁盘和 GPT 使用模板中的进度条。
- 点击 GPT 卡片（手动刷新按钮区域除外）在 `remaining`、`used` 之间切换并持久化。
- GPT 卡片中的刷新图标执行现有手动刷新；点击时阻止冒泡，避免同时切换显示模式。
- 删除刷新周期、代理输入和重置额度的界面。

### 刷新周期

前端和后端加载配置时都将 GPT 刷新周期规范化为 60 秒，避免旧数据库值继续生效。保留原字段以兼容现有序列化和数据库，不做数据迁移或删列。

## 代理配置

有效代理按以下优先级解析：

1. 启动参数 `--proxy <URL>`。
2. 程序运行目录下 `config.json` 的 `proxy` 字段。
3. 不使用代理。

配置示例：

```json
{
  "proxy": "http://127.0.0.1:7890"
}
```

开发模式的运行目录沿用项目现有规则，指向 `tbwidget` 工程根目录；打包模式使用可执行文件所在目录。空字符串表示不使用代理。参数缺少值、JSON 无法解析或代理 URL 无效时，记录中文错误并回退到下一优先级，不阻止系统指标和设置窗口启动。

现有数据库内的 `gpt_proxy_url` 字段暂时保留以兼容旧数据，但不再作为有效代理来源。

## DPI、分辨率和窗口尺寸

- 所有配置尺寸均视为逻辑像素，交给 Tauri/Win32 按当前窗口 DPI 转换为物理像素。
- 设置窗口在 100% DPI 下以模板约 384px 卡片宽度为基准，并保留外边距；工作区不足时按可用宽度收缩。
- 设置窗口高度取内容高度与当前显示器工作区可用高度的较小值，超出部分在内容区滚动。
- 显示设置窗口前、内容可见性变化后以及 DPI/显示器变化后，重新计算尺寸并定位到当前工作区右下角。
- 任务栏横向组件继续使用现有 `GetDpiForWindow` 逻辑宽度换算；显示器/DPI 变化后强制重新上报一次宽度并重新挂载/定位。

## 错误处理与日志

- 透明路径记录：Windows 构建号、所选实现、任务栏/XAML 目标查找结果、应用和恢复结果。
- 不在正式路径保留无上下文的 `println!` 调试输出；统一写入现有日志或带上下文的错误输出。
- Helper 加载或 XAML 目标查找失败时，任务栏保持系统默认外观，设置窗口和指标采样继续运行。
- 字体加载失败时使用系统字体回退，不影响交互。
- 代理解析失败时按优先级回退并记录原因。

## 验证

### 自动验证

- 前端执行现有 `npm run build`，验证 Vue 类型检查和 Vite 构建。
- Rust 主程序和 Helper 执行针对 Windows 目标的最小编译检查。
- 为纯逻辑部分增加最小测试：版本/路径选择、代理优先级、60 秒配置规范化、逻辑尺寸边界计算。

### 本机手工验证

- Windows 11 IoT 企业版 LTSC 24H2 上切换透明开关，任务栏背景在完全透明和系统默认之间切换。
- 重启 Explorer 后透明效果自动恢复。
- 切换常用 DPI 和分辨率后，设置窗口不超出工作区，文字和卡片不重叠；任务栏指标宽度重新同步。
- 设置窗口所有指标开关、日志、退出、GPT 卡片模式切换和手动刷新可用。
- 分别验证命令行代理、`config.json` 代理、无代理以及无效配置回退。

## 风险控制

- Windows 11 XAML 任务栏接口未公开，系统累积更新可能改变元素或接口。本轮将版本相关逻辑隔离在 Helper 边界，并在失败时安全回退到系统默认外观。
- Helper 进入 Explorer 上下文可能被安全软件提示。Helper 仅随本程序构建和加载，不下载远程代码，不修改系统文件。
- 不复制 TranslucentTB 源码，避免引入其实现耦合和许可证传播问题。
